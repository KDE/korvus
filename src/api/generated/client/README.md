POST endpoints accept application/x-www-form-urlencoded bodies, not JSON.
Authentication is supplied as form fields when creating a session; subsequent
writes use its secret sid. Share IDs and group PINs are distinct from session IDs.

Successful writes start with OK followed by LF-separated fields and a final LF.
Application errors usually return HTTP 200 with a human-readable body instead
of OK. Error messages are localized using Accept-Language (English fallback).
Missing POST fields produce \"Missing data!\\n\". Some authentication errors omit
the final LF. Clients must inspect the body, not just the HTTP status.

The PHP code does not set Content-Type for text responses; text/html is the
usual PHP default, although server configuration may change it. This definition
uses text/* for these bodies. Successful fetch responses explicitly use text/json.

## Documentation for Servers

Parameterized Servers are supported. Define a server in the API for each endpoint with arbitrary numbers of variables:

```
*.yaml:

servers:
- url: http://{server}:{port}/{basePath}
  description: Description of the Server
  variables:
    server:
        enum:
          - 'main-server'
          - 'qa-server'
          - 'dev-server'
        default: 'main-server'
    port:
      enum:
        - '3000'
        - '1000'
      default: '3000'
    basePath:
      default: v1
```
To change the default variable, use this function in each Api:
```
ServerError setServerVariable(const QString &operation, qsizetype serverIndex, const QString &variable, const QString &value);
```
The parameter "serverIndex" will choose a server from the server list for each endpoint.
There is always at least one server with index 0. The Parameter "operation" should be the desired endpoint operationid.
Variable is the name of the variable you wish to change and the value is the new default Value.
The function will return ServerError::ServerVariableNotFound when the variable does not exists,
ServerError::EnumValueNotFound if value is not defined in the variable enum,
ServerError::OperationNotFound if the operation is not found, and ServerError::ServerIndexNotFound
if there is no server with such serverIndex.

If your endpoint has multiple server objects in the servers array, you can set the server that will be used with this function:
```
void setServer(const QString &operation, qsizetype serverIndex);
```
Parameter "operation" should be your operationid. "serverIndex" is the index you want to set as your default server. The function will check if there is a server with your index.
Here is an example of multiple servers in the servers array. The first server will have index 0 and the second will have index 1.
```
*.yaml:

servers:
- url: http://{server}:8080/
  description: Description of the Server
  variables:
    server:
        enum:
          - 'main-server'
          - 'qa-server'
          - 'dev-server'
        default: 'main-server'
- url: https://localhost:8080/v1
```
